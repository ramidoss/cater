Chat

How a turn is framed, how much of the answer lives in the thread, and where the user's next action sits.

C1

Asymmetric bubbles

Today's pattern, tightened. The user's message is a right-aligned bubble; the agent answers flush-left with no container, so long answers read as a document rather than a shout. Structured findings sit in a tinted callout instead of yet another bubble.

Baseline · familiarAug 23

Across your last five broadcasts, open rate held near 38% but click rate swung by 3×. The spread tracks send time far more than subject line.

Top performer — “Your August rooms are live” (Aug 12, 9:05am): 44.1% open, 6.8% click, $4,120 attributed.
Underperformer — “A quick update from us” (Aug 19, 4:40pm): 31.2% open, 1.9% click, $310 attributed.

Move the next send to a 9–10am weekday slot and lead the subject line with the concrete noun (“rooms”, “August”), not the sender.

Ledger transcript

Full-width rows with a labelled gutter — speaker, time, and cost of the turn. Nothing is bubbled, so tables and charts get the whole column width. Reads like an audit log, which is the right register for a tool that spends money on sends.

Console

One line per event, monospaced timestamps, no avatars, actions on hover. Agent output, user input and system events share a single stream — which is the honest model, since the agent is writing to your account either way.

Reasoning

How much of the agent's work is visible, when it's visible, and whether it's there to reassure, to debug, or to prove.

R1

Summary disclosure

The current pattern with a real payoff inside. Collapsed it is one quiet line; expanded it shows typed steps with durations rather than raw chain-of-thought — enough to audit the approach without asking the user to read the agent's inner monologue.

R2

Live ticker

Answers the wait, not the audit. A single rolling line names what's happening right now in the user's vocabulary — “Comparing open rates”, not “calling metrics.rollup” — then settles into the R1 summary when the answer lands. Watch it run, or replay it.

Pairings worth building

Chat and reasoning aren't independent choices — density in one forces a decision in the other.

C1 + R2 → R1

Ship next

Keep today's bubbles, replace the silent wait with the live ticker, let it settle into the summary line. Smallest change with the largest perceived-speed win.

C3 + R6

The routine builder

Canvas holds the report, chat steers it, reasoning stays in the drawer. This is the shape if the agent's job is producing artifacts people re-run.

C2 + R5

The analyst

Full-width tables with per-claim provenance. Highest trust per pixel, and the only combination that survives a number being questioned.

C6 + R4

Operator mode

A density toggle rather than a separate product: same data, console rows and a raw tool trace. Cheap to add once R3's step schema exists.

One structural note: R3, R4 and R6 are three renderings of a single typed step log — {kind, label, args, ms, rows, detail}. Define that schema once and the reasoning variants become a display choice rather than three builds. R5 is the only one that needs new model output (claim↔source links).
